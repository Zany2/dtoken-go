# 性能优先重构实施方案

日期：2026-11-26。依据：[源码对比报告](performance-review_zh.md)。

本文记录性能重构的最终行为选择、实现进度和验收边界。A 批计数用例与主要基准、B—E 批主要代码改造已落地；用户授权后，F 批已完成全部 24 个非 SSO 模块的 vet 和非联网回归、现有 120 个 Auth 场景的 Memory 固定次数检查和完整重复测量，以及局部算法对照和真实池并发验证。真实 Redis 适配器测试通过，引擎回归因公网耗时按用户要求停止，随后完成 [Memory 方法审核](benchmarks/2026-11-26-memory-methods_zh.md)与补充回归。race 因缺少 CGO 环境受阻，完整 Redis 生命周期、实际部署负载与尾延迟、部署迁移演练尚未完成。最新证据见[验收记录](performance-acceptance_zh.md)，局部收益不代表整个框架或实际部署收益。SSO 不在范围内。

### 实施记录（2026-11-26）

方法审核后的[关键分支收尾](benchmarks/2026-11-26-memory-branches_zh.md)已完成：刷新消费前失败、异常刷新记录、登录清理失败与关闭异常的 16 个场景通过；删除 4 个无调用私有辅助方法，根模块及 Gin 流程的 vet、完整回归通过。未改变公开 API 或业务行为，剩余环境验收不作为继续扩大架构的理由。

以下保留各批代码落地时的验证状态，其中“尚未执行”描述当时状态；后续实际执行结果统一以[验收记录](performance-acceptance_zh.md)为准。新增 `BenchmarkAuthParallelWrites` 已纳入 Memory 固定次数场景检查，覆盖同账号和多账号的并发登录／退出，包含失败统计和残留终端核对。Memory 重复测量已发现并修复批量权限删除的大请求内存退步，保留小请求路径，并通过兼容性、事件及完整根模块回归；具体结果见[测量记录](benchmarks/2026-11-26-memory-report_zh.md)。

维护模块已补充真实 Ants 池组合测试：同 Token 并发合并、多 Token 池满回退、恢复重试、监听器共享池和关闭等待；在 GOMAXPROCS=1/4/8 下每场景重复 20 次通过。已有活跃／续期基准另测量 12 个配置组合各 3 次，完整维护成本和前台成本分开记录。本轮没有发现需要修改生产实现的缺陷；部署持续过载、尾延迟及 race 仍需对应环境验收。

Memory 工作负载现已收尾：全部 120 个 Auth 场景各 300 ms、重复 3 次通过，并发读写补充 GOMAXPROCS=1/8，结果及已测出的 Session 成本见[完整工作负载报告](benchmarks/2026-11-26-memory-workloads_zh.md)。本阶段主要源码改造与现有 Memory 矩阵完成；接下来执行剩余环境验收，不在没有具体缺陷或实际负载依据时继续扩大架构。

- A/F 批测量准备：新增公开 Auth API 到内置 Memory/Redis 的基准，覆盖基础校验、详情、活跃维护、自动续期、登录退出及手动续期，按终端数量和 Extra 大小组合；串行维护场景每轮排空任务并核对续期成功事件。另补终端凭据缺失比例 0%/50%/100% 的只读查询、Provider 命中／nil 回退／空列表拒绝、有限与永久 TTL 基础校验、同账号与多账号并发校验，以及每轮恢复残留快照的登录触发清理。见[基准使用说明](../../tests/gin_core_flow/README_zh.md)。尚未执行，不能据此认定性能收益；并发写入、维护过载和尾延迟测量仍待补齐。终端缺失由准备阶段删除主记录模拟，不覆盖真实到期过程；永久 TTL 基准不覆盖附属记录永久化。
- 新签发 Token 使用 `dtk:2:` 固定字段主记录；Extra 非 nil 时独立保存到 `token-extra:<accessID>`，空 map 与 nil 分开处理。签发、详情、自省、刷新、手动/自动/共享续期和退出路径已同步适配。
- `IsLogin`、`CheckLogin`、基础身份查询不调用通用 Codec 解码 Token，也不读取 Extra 或封禁记录。仍解析少量固定字段；未启用活跃超时时，基础校验前台只有一次 Token GET。启用的活跃超时和后台维护另计开销。
- 运行时命名空间已统一增加固定 `v2:` 段，覆盖 Manager 及 Nonce/OAuth2/Ticket/ShortKey；不回退访问无版本空间。主记录仍保留 AuthType。运行时 Token 已移除旧载荷的 Codec 解码、匿名生命周期写回及匿名身份比较；紧凑记录必须包含当前 AuthType 和非空 AccessID。封禁查询、写入与解封也已移除旧业务键回退，只访问规范键；缺少 loginId 或 kind 的记录须离线迁移。部署须先通过迁移工具转换数据，不能混用新旧应用处理同一逻辑认证体系。
- 详情接口在应有的 Extra 缺失或损坏时返回错误；基础校验与显式退出不依赖 Extra 可读。账号封禁仍保留废弃凭据元数据供查询，普通退出、踢出、顶替及刷新撤销清理对应扩展。
- 已编写格式边界、操作次数、扩展故障、续期、下线、冲突、旧格式拒绝、迁移后生命周期和刷新轮换用例，以及主记录解析基准。当前仅静态复检与 gofmt，**尚未运行测试、构建或性能基准**。
- C 批终端部分：普通登录未触达上限时不探测已有 Token；共享命中后不全量清扫，超过上限才整理；设备策略只整理目标作用域。拒绝策略遇到有效占位即停止，刷新轮换只检查原生命周期。已提供终端条目的有效性查询不再回扫 Session。临时设备封禁仍占名额，显式同值 Token 复用会替换旧索引条目。新增读取次数和作用域用例，尚未执行。
- 行为调整：未触发整理时，普通列表保留历史条目，仍存在的 Session 数据得以保留；有效列表及在线数量继续过滤失效项。共享续期不再写回未变化的 Session，登录触发整理后的 Session 写入已合并，具体边界见下文。
- C 批封禁部分：HTTP `CheckDisable` 显式检查账号、设备类型与具体设备，与登录及权限组合复用 Token 身份，并在维护任务提交前拒绝受限请求。自省、新登录和刷新签发仍执行限制检查。临时设备封禁不使基础校验失败；账号封禁已废弃的凭据仍无效。已同步示例、迁移文档及回归用例，尚未运行验证。
- C 批 Provider 部分：按 Token 的权限、角色查询和 HTTP 组合检查先调用 Provider，仅未配置或返回 nil 时加载 Session。非 nil 空列表拒绝访问，错误直接返回；权限和角色回退复用单次 Session 读取，权限失败后跳过角色查询。账号查询共用解析逻辑，未新增跨请求缓存。已补充读取次数、主体字段、缺失或损坏 Session、回退错误和调用顺序用例，尚未执行。
- D 批有效期部分：自动续期只读取 Session TTL，并按需延长，不再读取、编解码或写回其内容；手动续期及共享登录保留前置读取，但去掉无变化 Session 写回。活跃更新不读 Session；有限期 Token 续期直接 Expire，不再预先 Exists。新增可选 PersistentStorage，Memory/Redis 原生实现，普通存储使用原始值读写回退。Extra 永久化共用该能力。已补充操作次数、永久化、缺失键及续期前过期用例，尚未执行。
- D 批任务与值更新：Session 内容及未续期的活跃值更新接入可选 UpdateStorage，Redis 原生 SET XX KEEPTTL，Memory/普通存储使用 TTL + Set 回退。池拒绝后自动续期跳过并释放占位，活跃更新、显式强制维护和事件同步回退，不再新建 goroutine；TriggerSync 内联执行直接监听器。已补充契约、拒绝重试、活跃保留与事件投递用例，并同步文档，尚未执行。
- E 批独立能力：ShortKey 创建、确认、消费及撤销改为按凭据协调；Ticket 普通存储消费/撤销回退同样按凭据协调，空闲锁条目回收。三个 Service 撤销入口复用实际处理的记录，ShortKey 从最多 3 次 GET 降为 1 次，Ticket/OAuth2 从 2 次降为 1 次；OAuth2 令牌对删除合并为一次 Delete 调用。消费条件、消费状态及 Nonce 原子消费保持不变。已补充读取次数、事件、失败、重复撤销及不同凭据不互相阻塞的用例，尚未执行。
- E 批迁移准备：新增 `migration.Prepare/Apply`，支持停写窗口内同一 AuthType 的命名空间原始记录复制；预检只读，执行扣除已耗费 TTL、拒绝覆盖目标并保留源数据，失败报告部分写入且不自动重试或回滚。支持可选原子写入及普通存储回退。已补充边界用例和[使用说明](namespace-copy_zh.md)，尚未执行测试或实际迁移。

- E 批封禁迁移：新增 `migration.PrepareAuthUpgrade`，在同一预检快照中组合凭据与封禁转换；根据完整载荷及键恢复可判定的归属，规范化账号/服务/设备键并补齐 loginId、kind，保留各自 TTL、原因及等级。归属歧义、损坏数据或多个记录指向同一目标时拒绝预检，不写目标、不自动合并。已编写 JSON/Base64、封禁查询与解封、过期、冲突及重叠源键用例，尚未执行。

- 封禁模块收敛：四类封禁统一使用单键、单条记录读取，移除候选键去重、结果列表和重复转换；普通存储解封复用已核对记录，原子存储使用 GetAndDelete。等级、TTL、设备类型优先级和解封事件约定保留，旧键解释仅留在离线迁移及测试中。已补充各作用域的调用次数、旧键隔离、身份缺失和删除故障用例，尚未执行。

- C/D 批登录写入：过期终端整理、普通顶替、超限淘汰不再逐步持久化 Session；普通登录合并到一次最终保存，共享登录仅在列表变化后保存一次。全部旧名额失效时仍重建 Session，但以一次新写入替代中间删除和重建，并保持新 TTL、历史计数及事件规则。提前失败尝试保存已完成的清理，新 Token 写入失败保留原有回滚；失败路径不计入一次保存承诺。已补充账号/设备作用域、有限/永久 TTL、整会话编码次数、重建、策略失败、逐项淘汰失败及最终写入失败用例；仅静态复检，尚未运行。

- D 批手动续期附属状态：活跃标记有效期改用 Expire / Persist，有限期及支持原生永久化的路径省去校验后的再次 Get + Set；普通存储永久化复用原值读取回写，不增加接口或事务抽象。手动续期不刷新活跃时间，校验后缺失标记返回失败且不发布成功事件，不再补当前时间；保留已完成写入不回滚的策略。补充有限期缩短/延长、永久化原生及回退、关闭活跃检查、较新活跃值保留、标记消失与存储错误用例，并核对 Token/Extra/Session 的 TTL；同步续期中英文文档。仅格式化与静态复检，尚未运行测试或基准。
- C/D 批直接下线：Logout、Kickout、Replace 的前置校验复用轻量凭据路径，正常入口不再提前读取完整 Session；进入账号锁后为清理加载一次，Session GET/解码由两次降为一次。保留主记录捕获、生命周期复核、缺失 Session 回退、刷新归属检查，以及疑似不活跃超时时的上下文加载和锁内复核；主记录正常四次读取未在本批减少。扩展三个入口的成本矩阵、缺失/脱离/损坏/外部 Session、读取故障和超时原因用例，生命周期替换钩子移至锁前活跃读取，避免用例重入清理锁。对照 Sa-Token 的按 Token 下线流程，借鉴 Session 在终端清理时按需加载的做法，保留本框架现有超时事件语义。同步认证中英文指南；仅格式化和静态复检，尚未执行测试或基准。
- C/D 批授权算法：默认权限通配匹配改为 Cut 逐段比较，省去每次比较的两份 Split 切片，保留分隔符选择、整段通配、空段与精确匹配语义；自定义匹配器及角色精确匹配不变。权限和角色删除合并归属判定与筛选，使用请求大小的单个集合替代已有值集合及删除集合，原列表仅筛选一次，命中前不复制保留列表；保持请求顺序事件、重复值清理、原数组隔离及无变更不写入。删除已无调用的两个私有助手，更新原用例，补充旧算法对照、模糊测试、四类公开删除入口事件与写入计数，以及匹配/删除分配基准。同步权限指南；仅格式化及静态检查，尚未运行测试、模糊测试或基准，本批不减少存储往返。
- 待验收：按第 9 节执行跨模块回归、成本预算检查、并发与过载、真实 Redis 测量和迁移演练。大 Session、管理查询批处理、存储分片与搜索分页属于测量后的候选项，不作为已经确认的下一批改造。迁移工具不会自动修复无法判定归属的数据；歧义和重复封禁须由应用明确处理后重新预检。代码空间切换不等同于完成第 7 节的实际发布和验证。

## 1. 目标与实现边界

优先减少每次请求的存储往返、传输载荷、完整对象解码、重复遍历与无效后台任务。基础认证、完整详情、终端管理、访问限制分别承担自己的成本。

保留根包默认入口、AuthType 选择器、实例 API、组件契约和独立能力分层。性能问题主要在引擎调用链及数据布局，不再以重命名目录、增加 Builder 层次或调整门面包装作为这轮工作的主体。

公开方法名称能继续表达目标语义时保留；行为发生变化时同时更新契约、测试、适配器和文档。下述行为选择是本方案的实现基准，不延续所有历史行为，也不为每项历史差异增加配置开关。

## 2. 已选定的行为

| 项目 | 目标行为 | 相对当前版本的变化 |
| --- | --- | --- |
| IsLogin / CheckLogin | 检查凭据存在、状态及启用的活跃超时；成功后可安排维护 | 不隐式包含账号和设备封禁检查 |
| GetLoginID / GetDevice 等基础字段 | 复用轻量凭据校验并读取小字段 | 不加载 Extra 或 Session |
| 封禁检查 | 独立限制，按入口声明执行；新登录与刷新签发仍检查禁止签发的限制 | HTTP 组合检查显式承担 CheckDisable |
| 现有账号封禁动作 | 本轮保留“废弃已有凭据，解封不恢复”的行为 | 优化内部写流程，不把账号封禁悄悄改成可恢复登录 |
| 设备临时限制 | 继续可解除，不默认清除登录占位 | 基础凭据可有效，但需要该限制的访问检查必须拒绝 |
| 普通登录 | 不无条件扫描所有已有 Token | 允许终端索引暂时保留过期条目 |
| 共享登录 | 找到匹配且有效的候选即复用；维持原有共享登录续期行为 | 不清扫不相关终端、不重写未修改的数据 |
| 数量限制 | 按有效占位执行；临时设备限制不释放占位 | 达到候选数量阈值才核实，不用残留条目错误淘汰有效登录 |
| 普通列表和遍历 | 返回记录，不保证每项当前有效 | 保留当前轻量查询语义 |
| 有效列表和在线数 | 精确核对候选，过滤结果；不默认写回清扫 | 去掉逐项回扫 Session 的重复工作 |
| Token 详情 | 按需组装主记录和 Extra；不作为基础登录检查的前置条件 | 详情缺失不让主凭据自动失效，详情 API 独立报错 |
| AutoRenew | 保留当前默认开启及滑动 TTL 续期能力；与活跃刷新分开调度 | 不在本轮顺便改变默认会话寿命 |
| 活跃超时 | 仍同步决定当前请求是否有效；通过后的活跃刷新可异步 | 不把有效性判断推迟到返回成功之后 |
| 显式 Token 同值复用 | 保留支持，主记录保留独立生命周期 ID | 简化重复检查，不删除归属保护 |
| RefreshToken | 保留一次性轮换与独立生命周期 | 内部签发复用，不绕经重复完整登录校验 |
| Ticket / ShortKey 消费状态 | 保留 consumed 状态与现有约束校验 | 不为省写入直接破坏 Status API |
| 多 key 一致性 | 正常顺序生命周期 + 合适的单 key 原子能力 | 不引入通用事务、分布式锁或回滚框架 |

### 封禁与 HTTP 的连接规则

HTTP 已有 `CheckLogin`、`CheckDisable` 等声明，重构后应真实按声明组合：只有 CheckLogin 时执行基础认证；需要账号/设备限制时声明 CheckDisable。只检查封禁的 Token 请求，也需要先确定合法身份。

角色/权限判断不自动代表已经执行所有业务限制。现有框架 middleware、示例中原来依赖“登录检查顺便拦截设备封禁”的位置，必须明确补齐相应声明，并在迁移文档列出变化。不能只改引擎而让 HTTP 的 CheckDisable 成为无效字段。

账号封禁仍废弃已知凭据，但不能以此假设所有索引始终完整。需要严格执行禁令的受保护路由，必须执行限制检查；不能承诺仅靠 Session 索引批量撤销就能覆盖索引外的全部有效凭据。

## 3. 存储布局

### 3.1 主记录只保存热路径所需信息

Token 主键区分逻辑状态标记与 `dtk:2:` 紧凑凭据载荷；紧凑载荷保存身份、生命周期和 flags，不经过完整 TokenInfo 的通用编解码：

| 字段 | 必要性 |
| --- | --- |
| 状态标记（与紧凑载荷分开识别） | 主键缺失或逻辑标记表达失效；踢出、顶替、不活跃超时等原因不依赖详情判断 |
| AuthType | 读取时核对载荷所属认证体系，拒绝其他体系的数据 |
| LoginID | 身份返回、账号锁定位、Session 定位 |
| Device / DeviceID | 设备字段 API、限制检查和 Provider 主体，不为这些功能多读详情 |
| AccessID | 区分同一个 Token 文本的不同生命周期 |
| TerminalIndex / CreateTime | 终端归属、详情组装与既有管理行为 |
| Timeout / ActiveTimeout | 自动续期周期、单 Token 活跃超时覆盖 |
| HasExtra | 区分无扩展数据和应有但丢失的扩展数据 |
| Revoked | 与 HasExtra 编入 flags；账号封禁保留凭据元数据，同时保证解封后不恢复已有凭据 |

认证体系由无歧义的版本化命名空间隔离，紧凑载荷仍保存 AuthType，并要求与当前 Manager 一致；AccessID 必须非空。早期“省略载荷 AuthType”的设想未采用，当前保留显式归属校验。跨体系或旧格式数据仍须通过迁移预检核对，运行时不尝试旧格式回退。

主记录使用一个私有、固定格式的编码：版本前缀、固定字段顺序、带长度的字符串和明确的数值表示。只解析这些小字段，不经过通用 JSON/MsgPack 对象解码，不创建 Extra map。字符串长度约束、截断、数值溢出、未知版本和非法状态统一拒绝，账号字符串不能与状态哨兵混淆。

这不是新增公共 Codec 框架。现有 Codec 继续用于 Session、Extra 和独立能力对象；主记录编码仅服务引擎内部固定结构。实现时用分配和字节数基准验证格式，不为缩短几个字节引入压缩、反射或 unsafe。

### 3.2 只按需增加 Extra key

```text
版本化命名空间
  token:<token>              → 轻量凭据记录，TTL 决定绝对过期
  token-extra:<accessID>     → Extra，只有声明存在扩展数据时才创建
  session:<loginID>          → 账号数据与终端索引
  active:<token>             → 启用活跃超时时才使用的活跃记录
  refresh:<refreshToken>     → 独立刷新凭据
  token-refresh:<token>      → 撤销刷新凭据所需的反向关联
  其他限制/维护键            → 按对应功能使用
```

实际 key 的统一版本前缀沿现有命名空间构造器设计，不能只在某一类 key 上临时拼接。图中后缀表达职责，不是要求原样修改所有公开常量。

不额外保存一份重复的完整 TokenInfo。详情由主记录加 Extra 组成；无 Extra 的普通 Token 详情只需主记录。即使 Extra 是空 map，也应明确保存/还原其与 nil 的公开语义。

Extra 用 AccessID 绑定，防止同值 Token 的新登录读到旧扩展数据。签发准备 Extra 后发布可用主记录；发布失败时清理本次准备的数据。Extra 的有效期、续期、永久化和撤销必须与该生命周期一起处理。未启用 Extra 的登录、续期、退出不额外探测不存在的 Extra key。

对有 Extra 的凭据，完整详情读取增加一次 GET；签发/续期/撤销也增加维护工作。这是用低频详情操作换取高频基础校验的小载荷，必须在基准中同时展示读写两侧成本。

### 3.3 Session 暂不拆成多份

本轮保留 Session 的账号数据、权限角色回退值和终端索引结构，避免一开始就增加多份索引及一致性维护。

首先去掉不必要的读取和写回：基础校验不读 Session，Provider 命中不读 Session，续期不保存完整 Session。若之后测量证明大列表仍是主要瓶颈，再单独讨论拆分；不能为了取消 N 次 Token GET，就宣称包含 N 个终端的 Session 读写本身为 O(1)。

## 4. 各条主调用链

### 4.1 基础校验

```text
GET 主记录 → 检查状态并解析必要字段
                ├─ 失效：返回错误，不提交登录维护
                └─ 有效：按配置检查活跃超时 → 提交允许的维护 → 返回
```

未启用活跃超时的正常路径：1 次 GET、0 次详情/Session 解码、0 次同步写入。封禁、权限等组合检查额外计费，不隐藏在这个指标里。

活跃超时失败路径先保留必要的生命周期复核和下线语义，不在同一提交里把它改成纯读取冻结。后续如要改为 Java 式冻结，需要单独说明刷新凭据、事件和延迟活跃写入的行为。

### 4.2 登录与数量限制

1. 校验参数与本次签发限制；取得账号写范围。
2. 读取 Session 一次。
3. 共享允许时，只验证匹配候选；命中后不清扫无关终端。
4. 非并发拒绝策略只检查目标范围，发现有效占位立即返回。
5. 有数量上限时，候选数量未触达阈值不清扫；触达后只核实影响决策的范围，复用读取结果，再执行必要淘汰。
6. 写入本次终端和凭据，保存最终 Session；锁外发布事件。

共享候选本身可能有多个过期记录，查找最坏仍需要多次读取；目标是命中后停止、避免无关全量扫描，不承诺任何共享请求都只读一个候选。

无限终端、长期存活 Session 会保留历史项。本轮不增加后台全库清理器；登录策略与上限决策按作用域整理，显式终端注销更新索引。有效列表、在线数量等精确查询只过滤返回结果，不自动写回清扫。高频登录且无限制场景仍需承担索引增长及整份 Session 读写成本，后续按实际负载决定是否增加显式清理接口。

### 4.3 退出、踢出和封禁撤销

只读取身份和撤销所需数据，不先执行完整业务访问校验。必要的锁内生命周期复核保留，并让后续步骤复用取得的记录。批量删除附属键，Session 最终保存一次或删除一次。

撤销依据主记录和独立刷新关联，不能因为 Session 缺失、设备被限制或详情丢失，就让一个已识别的凭据无法下线。已过期 Token 无法解析身份时，不反向扫描所有 Session。

### 4.4 会话、权限和自省

- 按 Token 修改 Session：一次轻量身份定位，锁内一次所需复核和 Session 加载，修改后一次保存。
- 按 Token 查权限：先形成 AccessSubject，再调用所需 Provider；仅 nil 回退时加载 Session；空列表不是回退。
- HTTP 组合检查复用一次取得的身份和按需 Session。
- 本轮不先增加跨所有 Context 方法的认证缓存；优先在单次组合操作内复用。请求级缓存须等身份切换和写后失效规则明确后再实现。
- 自省继续明确返回完整信息，按实际需要读取 Extra、TTL、权限和角色，不宣称它具有基础校验的成本。

## 5. 续期与异步维护

### 5.1 存储能力只补真正需要的部分

引入两个职责明确的可选能力，不扩大基础 Storage 的强制实现要求：

- 更新已有值并保留 TTL：Redis 使用 SET XX KEEPTTL；普通实现按已有 TTL+SET 回退，说明其非原子窗口。
- 移除已有 key 的过期时间：Redis 使用 PERSIST；与现有 `Expire <= 0` 删除语义分开。普通实现可以在必要时读取并以无限期更新，不能误用 Expire。

上述能力已分别落为可选 `contract.UpdateStorage` 和 `contract.PersistentStorage`，不扩大基础 Storage 接口。缺失 key 必须可识别；无限期和不存在不能混为一类。

只延长 Session 生命周期时，读取 TTL 后按需要 Expire/Persist，不读取和序列化整个对象。Session 数据不存在时不借续期偷偷创建空会话。

Token 有限期续期使用 Expire 的缺失结果，不再 Exists+Expire。手动续期若修改后续续期周期，则更新小型主记录；Extra 和启用的附属数据同步维护生命周期。

### 5.2 任务成本与行为

保留按生命周期合并在途任务，任务携带已捕获的凭据生命周期。仅活跃更新的任务不读取 Session。工作线程在账号锁内先复核任务代次及续期资格；既无需续期也无需刷新活跃时间时尽早返回，不继续读取 Token 或 Session。资格检查本身仍可能访问 TTL 和节流键，不能描述为无锁或零存储访问。

本轮先取消不必要的任务内容和读写，**不默认引入跨请求成功认证缓存，也不先加入长期维护资格缓存**。后者需要实测判断是否值得，且会影响手动缩短 TTL、多实例续期与活跃精度。

移除池拒绝时无界新增 goroutine 的兜底，采用明确的有界行为：

- 可选的 TTL 续期任务拒绝时释放合并状态，记录失败，后续有效请求可重新尝试；不能把未续期报告为续期成功。
- 活跃更新直接影响闲置失效语义，不能按可丢弃日志处理；无法异步接收时采用同步更新回退，并计入请求耗时。
- 默认异步事件提交失败时，采用受控同步分发回退，避免默默丢事件；此时不承诺非阻塞。同步分发不得再走同一拥堵池嵌套等待。
- 自定义 Pool 必须满足契约；关闭后拒绝新增工作，已接收任务的等待与资源所有权不变。

这种选择限制资源扩张，但过载时可能增加请求延迟。实施时要用池拒绝、监听器重入、关闭等待等用例验证，不能只验证正常负载。

## 6. 非热路径和独立能力

- 事件无监听器、过滤器、统计或日志观察需求时，在分配载荷前返回；监听器合并排序移到配置变化阶段。EventAll 不能漏掉。
- 终端精确查询移除重复成员遍历，保留单次查询内状态复用；批量读取作为可选后续优化，不强制 Redis 数据类型或 Lua。
- 核心刷新复用内部签发流程及同一锁内已读取的记录，不新增公开 Builder；保留单次消费、撤销关联、独立有效期和旧生命周期保护。登录回调可改变状态，因此回调后的签发复核不能用回调前的快照替代。
- Nonce 保留原子读删，无须重构。
- Ticket/ShortKey 保留验证条件和消费状态；先检查实例锁对不相关 key 的影响，不直接改成“先删除再判断归属”。
- OAuth2 只复用同次流程内已校验的客户端、范围和凭据；不删 PKCE/redirect URI 检查，不套用普通登录的裸身份映射。
- 搜索分页、内存存储分片、通配符匹配等以基准结果决定，不在 P0 里无差别重写。
- 注册表生命周期锁、关闭等待和组件所有权保留；它们不在普通 Redis 登录校验的主要成本上。

## 7. 存储迁移与发布

主记录不再由用户 Codec 直接编解码，属于存储格式变更。采用新版本命名空间，运行时不每次尝试旧记录解码或旧 key 回退。

迁移要求作为实现交付的一部分，不在本轮文档工作中执行：

1. 在停写窗口读取旧格式，核对 AuthType 和生命周期，转换主记录/Extra/Session/刷新关联及必要状态。
2. 保留剩余 TTL，使用统一迁移时间基准扣除耗时，不把已到期记录迁成无限期；永久记录保持永久。
3. 账号、设备、服务限制必须迁移或由应用重新建立，不能因为换命名空间而消失。
4. 切换所有使用同一认证体系的应用版本；不默认支持新旧引擎同时写一组逻辑数据。
5. 若选择强制重新登录，可不保留登录凭据，但仍须处理禁令和应用需要的持久账号数据。不能仅“换个前缀”当作完整迁移。
6. 旧空间保留到迁移验证完成；清理必须作为单独、明确的部署动作，不能由新引擎启动时自动删除。

报告允许讨论破坏性设计，不等于授权现在清空生产或本地存储。迁移程序与部署步骤应先变成可审查交付物，再由应用决定切换时机。

## 8. 分批实施及验收

| 批次 | 主要范围 | 完成标准 |
| --- | --- | --- |
| A：成本基线与行为用例 | 核心计数型 Storage/Codec 测试、基准场景；不新建通用测试框架 | 用例准确记录同步/后台调用，列出有意变化的语义 |
| B：轻量凭据 | contract 文档、私有主记录、可选 Extra、签发/读取/退出/刷新/续期共同适配 | 基础有效校验 1 GET；无完整对象解码；生命周期一致 |
| C：终端与访问策略 | 并发控制、共享、精确查询、封禁组合、Provider 回退及 HTTP | 无条件 N 次清扫消失；无 O(N²) 成员检查；限制行为正确 |
| D：读写与维护 | 保留 TTL 更新、仅 TTL 续期、会话修改复用、撤销批处理、异步调度与事件 | 不变 Session 不重写；没有无界拒绝兜底；错误可解释 |
| E：独立能力与迁移 | 刷新调用链、OAuth2/短凭据的确定性优化、迁移与文档 | 不弱化一次性消费；跨模块 API 与新语义一致 |
| F：完整验证 | 回归、真实 Redis 基准、并发与过载、迁移演练 | 行为和操作预算均通过，再评价实际延迟/内存收益 |

批次是可审查的实现边界，不要求每批只改一个文件。涉及存储格式的 B 批必须完整适配所有读写方，不能只交付一个更快的 CheckLogin 留下损坏的续期/刷新。

仓库约定要求项目命令取得明确授权。本轮授权后已运行非 SSO 的 vet、回归、核心 race 命令及指定 Memory 基准，结果见验收记录；Redis 仅适配器全套完成，引擎回归已中止。持续模糊测试、完整 Redis 生命周期与负载、部署演练仍未完成。普通 `go test` 只执行模糊测试种子，不代表持续模糊测试已完成。不能把“非联网回归通过”或“局部测量通过”写成“完整性能验收通过”。

核心验收指标沿用对比报告的矩阵，同时记录有效性判定、封禁组合、活跃超时等不同语义配置，禁止用减少规则覆盖来冒充同语义性能提升。

## 9. 收尾验收清单

以下为完整验收标准；已完成的非联网模块回归及尚受阻／未执行项目见验收记录。先完成行为验证，再据实测结果决定是否扩展重构。

| 顺序 | 范围与现有入口 | 通过标准及需保留的证据 |
| --- | --- | --- |
| 1. 模块回归 | 根模块，以及 go.work 中非 SSO 的 codec、storage、logging、integrations、examples、tests 独立模块；应用流程见[核心流程测试指南](../guide/integration/core-flow-testing_zh.md) | 编译及相关测试通过，列明运行模块、工具链、失败和跳过项。根模块 `go test ./...` 不代表独立子模块全部覆盖；排除 sso 目录、sso/storage 和 examples/sso_* |
| 2. 操作预算 | internal/engine 中 validation、login、renewal、refresh、retirement、pruning、session_data、provider 等计数用例；event、oauth2、ticket、shortkey 的对应测试 | 按入口、配置和存储能力分别记录 GET/TTL/SET/EXPIRE/DEL/原子调用及 Codec 次数；后台成本单独计数，不能只统计返回前的操作 |
| 3. 生命周期与并发 | 同值 Token 替换、即时撤销、活跃边界、刷新消费、监听器重入、池拒绝、关闭等待；执行适用的 race 检查 | 没有数据竞争、死锁、旧任务污染新生命周期或错误事件；普通存储回退按声明的顺序语义验收，不声称跨进程事务保证 |
| 4. 性能测量 | 已有 BenchmarkTokenRecordDecode、BenchmarkScopedTerminalQueries、BenchmarkManagerTokenKey、BenchmarkEventDispatch、BenchmarkPermissionSegments、BenchmarkAccessRemoval，以及 tests/gin_core_flow 的 BenchmarkAuth 系列（公开 API 到真实存储，含查询、写入、永久校验、并发读写与登录清理） | 保留基线版本、配置、数据规模与原始结果，比较 ns/op、B/op、allocs/op、传输量和端到端延迟。基准不经过 HTTP；RunParallel 度量并发校验或登录退出的吞吐成本，不能当作单请求延迟或 p95/p99。已有 Memory 局部实测；维护过载、尾延迟、传输量及真实 Redis 测量仍待补齐 |
| 5. 迁移演练 | migration 的 namespace、tokens、auth、version 用例，以及[迁移说明](namespace-copy_zh.md)中的停写升级流程 | 在隔离数据上验证同前缀升级、目标冲突、TTL 扣减、身份/封禁归属、刷新关系及迁移后登录生命周期；保留源数据，失败报告部分写入，实际部署单独确认 |
| 6. 发布收敛 | 将通过记录回填本节，核对迁移说明与公开 API 文档 | 已知失败全部处理，跳过项有明确原因，行为变化和实测收益分开说明，再标记对应批次验收完成 |

真实 Redis 验收需要确认测试实际连接 Redis，没有因环境缺失而跳过。引擎测试入口使用 `DTOKEN_MANAGER_TEST_STORAGE=redis` 和 `DTOKEN_REDIS_URL`；Redis 存储及 HTTP 流程测试读取 `DTOKEN_REDIS_URL`。引擎套件中明确构造内存存储的用例仍只验证内存路径，不能仅凭环境变量把整套结果称为 Redis 覆盖。

负载矩阵至少包括：1/10/100/1000 个终端、0%/50%/100% 过期残留、无 Extra/1 KiB/64 KiB Extra、Provider 命中/回退、有限/永久 TTL，以及同账号和多账号并发。授权删除同时比较“小请求、大账号列表”和“大请求、小账号列表”，避免只展示有利于请求集合方案的样本。性能对比必须保持认证规则和配置一致，有意改变的语义另列。

以下候选项等待上述数据再决定：大 Session 拆分、终端批量读取、内存存储分片、搜索分页，以及直接下线主记录重复读取的进一步合并。当前直接下线仍保留正常路径四次主记录读取，资格检查仍在账号锁内执行；这些是已知成本，不应在没有生命周期证据或测量的情况下直接删掉。跨请求认证缓存、强制事务及后台全库清理不纳入本轮默认范围。
